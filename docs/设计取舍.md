# 设计取舍

这份文档只记**为什么这么选**和**选了的代价**。怎么装、怎么配、字段什么意思，README 里。

写给两种人：一是想改它的人（先看这里，免得把踩过的坑再踩一遍），二是想判断要不要用它的人
（看代价，别看功能表）。

---

## 一、最大的一个取舍：灰模式，只记不拦

**选了什么**：检测到疑似退化，只往 `events.jsonl` 写一行，**不动那一轮**。不 `agent.cancel()`，
不塞自定义 `finish.kind`，不改落库内容，不拦一个字。

**为什么不拦**：

1. **拦错了没法赔。** 一次误判中断，用户丢了半轮输出，而这个插件赔不出东西来。反过来，记漏
   一行只是少一个数据点。两种错的代价不对等，就先选代价小的那边。
2. **判据还没验够。** 阈值全是拍的（见第七节），没有一条经过真实数据的分布检验。拿没验过的
   判据去中断对话，等于拿用户当测试集。
3. **有个前置的坑没人趟过**：预研查过 `dsh-llm-retry`，它把 `finish.kind` 当**可重试**处理。
   也就是说，如果为了「优雅地结束」去伪造一个 `finish.kind`，退化轮会触发重试——**想省钱反而
   更烧钱**，而且重试出来的还是退化。这个坑没填，拦截就不该上。

**代价**：一周里它只会告状，不会救人。退化真发生时，用户看到的还是退化输出。这就是为什么它
现在带 `enable` 开关和 `disabledSessions`——先当观察哨用，不当保安。

**什么时候该改主意**：一周数据的误报率能算出来了、判据分布摸清了、`finish.kind` 那条路验通了。
三个都齐，才谈拦截。

## 二、为什么扫 `reasoning-delta`，不扫 `text-delta`

退化（「好。做。做。做。」这种填充循环）**先出现在思考里**，再污染正文；很多时候正文已经被
它自己掐掉了，思考里还留着几千遍。

扫正文的另一个问题是**误报高**：正文里重复是正常的——代码块、表格、列表、强调句，全是重复结构。
思考里的重复才有诊断价值。

**代价**：只扫思考，等于漏掉「不思考直接退化」的那类。目前的判断是这类很少（退化本身是思考
失去进展的表现），但**没有数据支撑这个判断**，属于待验。

---

## 三、三个信号：各抓一种形态，不是三个阈值堆在一起

| 信号 | 抓什么 | 判据 |
|---|---|---|
| A | 单字符连续重复 | 同一**非 ASCII** 字符连续 ≥ `run` 次 |
| B | 少数几个词霸占窗口 | 「好/做/嗯/继续/好的」占比 > `ratio` 且各自计数 > `minCount` |
| C | 短 n-gram 连续重复 | 长度 `minGram`~`maxGram` 的片段连续重复 ≥ `repeat` 次 |

**为什么 A 限定非 ASCII**：第一版没限，在 `dsh-recall/lib/index.js` 上误报 13 次——`"0" x5` 来自
`86400000`，`"x" x8` 来自进制/坐标类的写法。**代码里的 ASCII 重复是设计，不是退化。**

**为什么 B 的分母是非空白字符**：第一版用窗口总长。真实退化 `abcdef12` turn 344 里「好」占
**非空白字符的 9.3%**，按总长算只有 4% 出头，永远够不到 15%。换成非空白做分母，那个数才
反映「这句话里有多少是废话」。

**为什么 C 要「连续」重复**：C 的第一版是「n-gram 在窗口里出现 ≥8 次（可重叠）」，在
`dsh-flow/lib/index.js` 上 **210/210 帧全部误报**。第二版改成不重叠 + 跳过纯空白片段，还有 58。
第三版要求**连续**重复才降到 0。**「出现很多次」和「连着出现很多次」是两件事**，只有后者是退化。

**为什么 C 是主力而不是兜底**：真实退化文本（`abcdef12` turn 377，44,608 字符）里，单个「做」
出现 3202 次 = 非空白字符的 **9.4%**，但**最长连续「做」只有 1 个**——每个「做」后面都跟着
「。」和换行。所以 A 抓不到（要 ≥8 连续），B 抓不到（9.4% < 15%），**只有 C 抓得到**，靠的是
「做。\n\n」这个 4 字片段连续重复。真实数据里 C 占 94% 的触发，不是因为它过敏，是因为
**它是唯一认得这种形态的信号**。

**代价**：三个信号各管一段，加起来仍然覆盖不全（比如「每段都不同但每段都是废话」这种）。
一周数据的价值就在这里——看漏了什么形态。

## 四、为什么零依赖

`~/.dsh/plugins/` 下**没有 `node_modules`**。插件靠 `link:` 装进来，`@deepseek-ai/*`
这些核心包在这个目录里根本解析不到。

这不是这台机器的毛病，是这类插件的通用处境：**插件被装进一个不知道会有什么依赖的目录**。

**代价**：配置校验得手写（不能用 `schemastery`），默认值要自己兜一层，JSONL 要自己拼。
这几十行代码换的是「装到哪都能跑」。

顺带一个教训：子会话当时报信问「`@deepseek-ai/schemastery` 能不能解析到」，我实查确认不能，
才改成零依赖。**这个坑是它问出来的，不是我想到的。**

## 五、为什么写 JSONL，不写数据库

1. **追加即安全**：`fs.appendFileSync` 一行一条，进程崩了最多丢最后一行，不会写坏前面。
2. **工具链现成**：`grep` / `jq` / 一行 Node 就能查，不需要为了看个数先连上数据库。
3. **人能直接读**：出问题时 `tail -20` 就能看，不用先学 schema。

**代价**：只能顺序扫，数据量大了慢；没有索引，按 session 查要自己 `grep`。**一天 700 行左右的
量级，这些代价都不用付。** 真到十万行再谈换，现在换是过度设计。

## 六、为什么把 `roundFinalChars` 单独拆一条 settle 行

触发那一刻，这一轮还没结束，**最终字数根本不知道**。所以触发行里先写 `roundFinalChars: null`，
等 `turn/end` 事件到了，再单独写一条 `settle` 行，靠 `turn + attemptId` 对上。

**这个字段是留给一周后回答一个问题的**：「触发之后，这一轮到底输出了多少？」如果触发轮的最终
字数跟正常轮没差别，那这些触发**不影响产出**，误报而已；如果明显更短或更长，那才是真问题。

**代价**：每次触发写两行，`events.jsonl` 大一倍；查询要 join 两次。这个代价换的是**事后能算
出「触发的影响」而不是只有「触发的次数」**——后者没有决策价值。

## 七、阈值哪个是实测的，哪个是拍的

**没有一个阈值是拿真实分布调出来的。** 全部来自需求文档和常识，这条必须写清楚，否则后面的人
会以为它们有依据。

| 参数 | 值 | 来源 | 可信度 |
|---|---|---|---|
| `windowChars` | 2000 | 拍的 | 未知 |
| `signalA.run` | 8 | 实测：5 会在注释里误报，8 归零 | 中（两类文档验过） |
| `signalB.ratio` | 0.15 | 拍的 | **低，已知够不到真实退化（实测 9.4%）** |
| `signalB.minCount` | 12 | 实测：50 够不到单 attempt | 中 |
| `signalC.minGram` / `maxGram` | 4 / 16 | 拍的 | 未知 |
| `signalC.repeat` | 8 | 实测：从 8 起到 0 误报 | 中 |
| `trigger.consecutive` | 2 | 拍的 | 未知 |
| `trigger.repeatChars` | 500 | 拍的 | 未知 |
| `reasoningTokensEst` | `chars / 1.6` | 拍的 | 只给量级感，**不参与任何判定** |

**已知最该改的是 `signalB.ratio`**：真实退化的「做」占比 9.4%，`0.15` 永远够不到。0.1.4 一天
数据的 8 条触发里 B 是 **0 条**。一周后要动的第一个数就是它。

## 八、`sample` 为什么必须脱敏

0.1.4 之前，触发行只有统计量。知道「这一轮触发了 52 次」，**判断不了是真退化还是误报**。

真实教训：为了判断 turn 377 是不是真退化，得去解会话存档——15MB 的 zstd 多帧拼接、每行双重
JSON 编码、翻 18,878 行。**就是为了看一眼「它到底在重复什么」。**

所以加了 `sample` 存命中形态。但它存的是 reasoning 原文的一小段，里面可能有路径、会话 id、
邮箱、密钥。**不脱敏就是往日志里写私人信息。**

脱敏只做有明确形状的替换（`<PATH>` / `<SID>` / `<EMAIL>` / `<NUM>` / `<KEY>`），**不做泛化
删除**——全删成 `<MASK>` 就白存了，而 sample 本身只有 4~16 个字。

**踩过的坑**：第一版邮箱正则用 `[\w.+-]+@…`，`主人@example.com` 漏了——`\w` 不含中文。改成按
「@ 两侧的非空白」判。

---

## 九、已知的洞

- **拦不了**：灰模式下退化真发生时它不救人，这条是设计，不是缺陷。
- **只看思考**：不思考直接退化的形态漏掉。
- **阈值没验完**：第七节表里一半是拍的。
- **一周数据前的判断都不可靠**：230/245 的 C 触发是不是真的，要等 `sample` 攒够、人工看过才算。
- **`repeatChars` 曾经算错过**：0.1.3 之前只并了 A 和 B 的位置，C 一个没算，导致 C 单独触发时
  `repeatRate` 恒为 0。而 C 占 94% 的触发。**0.1.2 及以前的行的 rate 对九成触发是假的，不能
  拿来定阈值**，统计时必须按行里的 `pluginVersion` 分组。
- **`enabled` 曾经不校验类型**：`"false"`（字符串）是真值，所以「以为关了其实在跑」。0.1.5 修。

**已知的洞都堵了，不等于穷尽。**
